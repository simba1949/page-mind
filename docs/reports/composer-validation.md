# 输入框焦点与粘贴验证

日期：2026-09-08

## 后续回归：Chrome 点击输入框后仍粘贴到地址栏

用户确认原修复后仍可复现：新建标签页、打开页知、点击输入框、Ctrl+V，内容进入地址栏。因此下文原有 DOM 测试结果不代表原始问题已解决。

本轮调整：工具栏入口使用 `openPanelOnActionClick: true`，移除重复的后台 action 点击处理；输入框的补偿聚焦从 pointerdown 改到 click，避免在原生鼠标聚焦和选区定位之前执行 blur/focus。右键菜单继续在用户手势中调用 sidePanel.open。

新增后台入口行为测试覆盖原生打开配置、无重复点击处理、配置失败处理、右键打开时序及非法消息拒绝。全量结果为 12 个套件、146 项测试通过，类型检查和构建通过，dist 已更新。

当前没有可连接的 Chrome 自动化实例，本轮调整仍待真实浏览器验证，不能宣称根因或修复效果已经证实。重新加载扩展后须复测上述用户步骤，同时检查普通网页、拖选文本、关闭并重开侧栏，以及设置输入框中的粘贴。

参考：[Chrome 官方工具栏打开侧栏 API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel#open-action-icon)。该文档支持所用 API，不构成本问题已解决的证据。

## 变更范围

将焦点恢复、自动聚焦条件、原生粘贴目标识别、纯文本插入提取到 `src/sidepanel/composer.ts`。控制器保留事件注册、设置弹窗守卫和附件处理，不引入新的服务层或运行时依赖。新增的 jsdom 环境仅用于测试。

补强已取消事件和富文本编辑区的保护；自动聚焦跳过隐藏文档；快捷键处理跳过输入法组合状态及 Alt 组合键。

## 验证边界与待执行的浏览器验收

DOM 测试使用 jsdom，不能模拟 Chromium 地址栏、侧栏挂载动画、系统剪贴板默认操作或真实鼠标光标定位。本次没有完成真实 Chrome/Edge 扩展端到端验收，也没有把单元测试通过视为这些场景已通过。

1. 重新加载 dist 扩展，打开新标签页与侧栏，点击输入框后 Ctrl+V；文字应进入输入框，地址栏不变。
2. 侧栏保持打开，再开新标签页，重复上述操作；选区替换、连续粘贴和右键粘贴均应正常。
3. 在模型请求缓慢时打开侧栏，输入框应可立即操作；打开设置后，延迟聚焦不能抢走 API Key 输入框焦点。
4. 粘贴图片仍应进入附件流程；粘贴恶意 HTML 应显示为文本，不执行脚本或自动发送消息。
